# DSH Bridge（dsh-cockpit）

给 DeepSeek Harness Web 对话界面套上「未来舰桥」外壳。纯客户端 UI 插件，不改任何业务逻辑。

当前版本 **v16.14.0**（2026-11-06），实测对齐 DSH `0.2.2-rc.1`；升级 DSH 后若类名失配，见《宿主改造》一节的重新对齐方法。

> v15.0.0 事故记录：取景框探针（composer dock 内 flex 1 1 100%）把整行挤扁，全局布局错乱，
> 已整体回滚。另发现星点 CSS 括号不配对（rgba 吞掉渐变收尾）——v15.1 起重做并加
> **构建期 CSS 括号平衡自检**（localhost/127.0.0.1 下 console.error 报警）。
> 装饰件改为**一件一装一验**：v15.1.0 = 星野底（仅此一件，纯背景层，零布局风险）。

## 快速安装（给别人用就看这一节）

只支持 **DSH Web**（纯客户端插件），不需要编译。把仓库链接丢给对方的 DSH 即可，也可以自己执行：

```
plugin_manager install_bundle github:Radicas/dsh-cockpit
```

不想发 GitHub 链接，就把 GitHub Releases 里的 `dsh-cockpit-16.14.0.tgz` 发给对方，用**绝对路径**安装：

```
plugin_manager install_bundle /绝对路径/dsh-cockpit-16.14.0.tgz
```

装好后刷新页面，在 Settings → Plugins 里能看到 **DSH Bridge**。卸载：

```
plugin_manager remove_bundle dsh-cockpit
```

实测对齐 DSH `0.2.2-rc.1`。对方的 DSH 版本不同也能装上，但宿主样式覆写（输入卡片、消息气泡、上下文圆环）可能不再命中；侧栏 HUD 等插件自有 UI 不受影响，重新对齐方法见《宿主改造》。

## 面板定位改为自测量（v16.13.3）

v16.13.2 修错了一次，记录在这：当时只拆掉了 composer seat 的 `will-change`，
但输入行 `.uV2eYG_row{container-type:inline-size}` **同样生成包含块**。
拆掉较高的那个，最近的包含块就变成只有约 50px 高的输入行，
`top:92px;bottom:200px` 算出**负高度**，面板全部隐身。

### 结论：不要跟宿主抢，改成自己量

侧栏不再假设 `position:fixed` 相对视口。现在的做法：

1. 把列摆到**包含块原点**（`top:0;left:0;right:auto;bottom:auto`），显式给高度
2. **量** `getBoundingClientRect()`，得到它实际落在视口的哪里
3. 用 `translate()` 补差值，落到目标视口坐标（y=92，左栏 x=侧栏宽+14，右栏 x=视口宽-16-栏宽）

它对宿主将来新增任何 `transform / filter / will-change / contain` 都免疫，
因为它不关心包含块是谁，只关心量出来的结果。窗口 resize 与侧栏宽度变化时重算。

同时撤掉了 v16.13.2 对宿主 `will-change` 的改写——那是宿主为滚动性能加的，不该动。

## 面板掉到下面（v16.13.2）

现象：所有侧栏面板跑到对话区底部、挤在输入框那一带。

### 根因是宿主的一行 `will-change`

```
.wSkVaW_composerSeat{ ... will-change:transform; position:sticky; bottom:0 }
```

`will-change:transform` 和 `transform` 一样，**会把元素变成 `position:fixed` 子元素的包含块**。
我们的侧栏注册在 `conversation.composer.dock`——输入框底座内部，于是 `position:fixed`
不再相对视口，而是相对**贴着对话区底部的底座**。所有面板一起掉下去。

### 修法：换一个不生成包含块的图层提示

不能直接删 `will-change`，那是宿主为滚动性能加的图层提升。改成 **`will-change:opacity`**：

| 值 | 提升图层 | 生成包含块 |
|---|---|---|
| `transform` | ✓ | **✓ 会** |
| `opacity` | ✓ | ✗ 不会 |

`opacity` 只创建层叠上下文，不创建包含块，所以图层保留、`fixed` 恢复。

### 加了运行时哨兵

这类故障是**静默**的：DOM 正常、React 正常、控制台干净，只有位置错。
现在挂载 600ms 后测一次左侧栏的 `getBoundingClientRect().top`，偏离 `92px` 超过 48px 就在
控制台喊一声，并说明原因。下次宿主再加任何 `transform/filter/will-change/contain` 都会立刻暴露。

### 附带修掉的

- 去掉 `left` 过渡：加载时两栏会从默认位置"滑"到实测侧栏宽度，看起来像面板在飞
- 侧栏宽度测量加合法性钳制（120–560px），异常值退回 CSS 默认，不把左栏甩到对话中间
- 列与面板加溢出裁剪

## 以太粒子（v16.13）

打字时，以太从输入框飞进充能环。

**它是真的触发，不是自嗨动画**：只有草稿字数**增长**才发射——删字不发射、粘贴 4000 字只发 3 颗、
空输入与没装语音时什么都不飞。

### 实现

- 一块 `position:fixed` 的 canvas（DPR 上限 2），`pointer-events:none`，z-index 9998
- 每颗粒子走**二次贝塞尔**：起点取输入框内的近似位置 → 控制点下压 30px（让弧线沉下去）→ 终点是充能环中心
- 缓动 `u = u0²·0.82 + u0·0.18`：先慢后快，像被环吸进去
- 粒子 520–780ms，途中画 8.5% 的拖尾；抵达时在环心放一圈扩散闪光
- **加法混合** `lighter`，所以叠加处自然变亮
- 并发上限 40，单次击键最多 3 颗

### 性能纪律

- rAF 循环**只在有粒子时存在**，粒子与闪光清空后立刻 `cancel` 并清屏，不留空转
- 尊重 `prefers-reduced-motion: reduce`：命中就整个不挂载
- 插件卸载时移除画布与监听

### 新增 `ethercheck.cjs`

自检只能证明代码不报错，**证明不了粒子会画、会消灭、循环会停**。这是第二个门禁：

```
$ node ethercheck.cjs
  ok  canvas mounted 2880x1800 (dpr 2 of 1440x900)
  ok  54 frames, 157 strokes, 103 fills, loop stopped cleanly
  ok  dispose removed the canvas
ETHER-CHECK PASSED
```

它用假 DOM + 手动驱动的 rAF 跑完整生命周期，并断言三件事：发射只排一帧、循环在粒子消灭后
**必须停止**（不停就是耗电 bug）、卸载后画布不残留。装包前三个门禁全过：`node --check`、
`selfcheck.cjs`、`ethercheck.cjs`。

## 只有光，没有键体（v16.12）

充能这个概念保留，键体取消。

**为什么六角形是错的**：这套 UI 里所有面都是「矩形 + 45° 切角」（面板、芯片、牌面、矢量条），
六角形是另一套语汇；而且 38px 的尖顶六角看起来像螺帽，不像未来。

### 现在两个键 = 虚线圈 + 一个符号

- **虚线环** = 空槽，还没有被充能
- **亮弧**贴在虚线圈上 = 真实充能，长度就是草稿字数（`--dsh-charge`）
- 空草稿 → **亮弧为零**，只剩一圈虚线，是看得见的缺口；写字时缺口逐渐闭合
- 悬停 → 虚线圈开始缓慢旋转
- 按下 → 环收缩

**没有键体带来两个副作用，都是好的**：不用 `clip-path`，所以外发光可以直接用 `drop-shadow`
而不被剪掉；composer 那一行也不再被一个实心块压住，透气了。

语音键同族：紫虚线圈；未配置转琥珀；录制时真实振幅波形 + 向外扩散环。

## 充能核心与声纹发射器（v16.11）

上一版只做了"形状 + 光晕"，那还是个按钮。这一版把两个键变成**有行为的东西**。

### 发送键 = 充能核心

深色六角凹槽，**边缘那道弧的长度 = 你真实草稿的字数**。
每敲一个字弧就长一点，写到 120 字弧满。空草稿时整圈是暗的。

- 弧长来自 `input.draft.length`，经 `--dsh-charge` 写到元素的 CSS 变量上
- 没有草稿 → 弧为零。这个键不可能"假装"在充能
- 悬停 → 一道光沿边缘旋转一周（2.2s）
- 按下 → 凹槽收缩，光爆一下

⚠️ 120 字是**显示上限**，不是测量值。弧会饱和，草稿不会。

### 语音键 = 声纹发射器

紫色六角，三种真实状态：

| 宿主状态 | 表现 |
|---|---|
| `aria-haspopup="dialog"` | 转**琥珀**——宿主明说点了会开设置，即语音未配置 |
| `data-voice-activity="recording"` | 琥珀热核 + **向外扩散的环**（1.6s 一圈） |
| `disabled` | 压暗成未通电的凹槽 |

旁边那道波形是**语音插件自己的真实振幅 SVG**（`ddpbLW_waveform`），我只改了颜色和光晕，
没有生成任何图形——它的每个起伏都来自实际麦克风采样。输入电平条同理。

### 技术要点

- 外发光一律 `drop-shadow`：`clip-path` 会裁掉 `box-shadow` 的外阴影
- 充能弧用 `::before` 的 `conic-gradient` + `radial-gradient` 遮罩做环，弧长即 `--dsh-charge`
- 旋转光用 `::after` 的第二道 conic 遮罩环，仅悬停时启 `animation`
- 扩散环挂在 `.ddpbLW_triggerAnchor`（无 clip-path 的父级）上，否则会被六角形剪掉

## 控制台键（v16.10）

发送键与语音键重做成同一套几何：**八角形**，与面板的切角语言一致，只靠通道色区分。

| 键 | 形状 | 通道色 | 真实状态 |
|---|---|---|---|
| 发送 `.uV2eYG_primary` | 36px 八角 | 青 | `:disabled` = 草稿为空（未上膛） |
| 语音 `.ddpbLW_trigger` | 32px 八角 | 紫 | `:disabled` = 锁定；`[aria-haspopup="dialog"]` = **未配置**（点了开设置） |

**每个视觉状态都对应宿主真状态**：未配置时转琥珀、录制中呼吸——后者直接挂语音插件自己的
`data-voice-activity="recording"` 属性（用 `:has()` 选择），不是猜的。

### 一个必须修的坑

`clip-path` 会**裁掉 `box-shadow` 的外发光**——外阴影画在形状外面，正好被剪。
所有外发光改用 `filter: drop-shadow()`，它按裁剪后的形状绘制；`box-shadow` 只保留 `inset`。

语音键此前完全没有主题化（宿主原样），这次一并纳入。

## 层级收敛（v16.9）

两档放大之后暴露出真问题：**9 个字号层级挤在 8.5–13px 之间**，相邻两级差 0.5px——
浏览器会渲染亚像素，人眼分不出 10.5 和 11。等于编码了一堆看不见的差别，层级反而等于没有。

### 收敛到四级

| 级 | 字号 | 用途 | 数量 |
|---|---|---|---|
| **主视觉** | 22px | CTX 百分比、启动标题 | 2 |
| **面板主读数** | 14px | 每块面板恰好一个焦点 | 3（另 AGENT 状态行 / FLOW 相位名各一） |
| **正文** | 11px | 标签、行读数、芯片、用量行 | 18 |
| **微字** | 9px | 波形泳道、闪字、台账标题、型号 | 5 |

**每块面板只留一个主读数**（新增 `.dsh-br-headval`）：CTX 占用上限、MIX 构成总量、USE 累计用量。
AGENT 的主读数是运行状态（RUN/IDLE，14px），型号 `MK-IV` 压到 9px 次级色。
FLOW 的主读数是相位名（14px）。

### 顺手去重（层级不清往往来自重复）

- FLOW 顶栏原本显示累计 tokens，与 USE 面板**完全同一个数**——改成该面板自己的吞吐 `t/s`
- 运行行里的"运行中工具数 `▸n`"与台账的 `TOOLS n` 重复，删掉前者
- 待确认按钮从「跳转」两个汉字改为 `⚑` 符号，说明移进 `title`

### 宽度算术审计（首次做）

放大两档后，按等宽字体（拉丁 0.6em / 中日韩 1em）逐个核算最宽的一行：

| 最坏情况 | 需求 | 可用 | 结果 |
|---|---|---|---|
| AGENT 运行行（运行+待确认+长会话） | 188px | 196px | 96%，计数带省略号 |
| CTX 弧 + 读数（100 万上下文） | 226px | 224px | 101%，副行带省略号 |
| USE 用量行 | 197px | 224px | 88% |
| FLOW 生物行 | 172px | 196px | 88% |

两条超过的都加了 `min-width:0` + `text-overflow:ellipsis`，**超了会截断而不是顶破**。
数字读数同时去掉宽字距（`.16em` 是给拉丁标签的，压在数字上纯浪费宽度）。

## 虚空生物（v16.6）

相位指示器彻底换形：**取消位置轴**。

三轮迭代（7px 圆点 → 生命核 → 站点轨道）都不满意，根因不在美术：**相位是分类变量，
不存在次序，硬编码成"线上位置"就必然编出一个假维度**——刻度、站点、格子都只是给假维度补妆。

现在是固定一点的一只生物，**相位写在身体上**：

| 相位 | 内核 | 膜 | 瓣 | 读法 |
|---|---|---|---|---|
| 待机 | 小暗 | 细实线 | 收拢 0.42 | 蜷着 |
| 输入 | 暗青 | 实线**开口朝你** | 半张 | 在听 |
| 提交 | 猛缩一次 | 闭合加粗 | 收回 | 咽下去 |
| 思考 | 中青 | **虚线慢转** 3.4s | 内收 | 在转 |
| 工具 | 中紫 | **两段反向转** | 外张如抓 | 在抓 |
| 输出 | 绿色 | 实线 + **向外推波** | 节律张开 | 在说 |
| 待确认 | 亮琥珀 | **顶部开缺口** + 瞳孔放大 | 停住 | 在看你 |
| 出错 | 暗红 | **断成三截** + 停止运动 | 塌下 | 碎了 |

**真数映射**：输出时膜的波频与内核缩放由**真实字/秒**驱动（量化到 0.1s 避免每拍重启动画）；
`think` 旁的秒数来自 `stats`/`thinkMs`，`tool` 旁是真工具名，`type` 旁是真实草稿字数。
只有"相位→活度档位"这组系数是设计选择，README 明示不含糊。

**布局**：位置轴取消，原来的 `YOU / ME` 锚点一并删掉，改成一枚生物 + 相位名 + 该相位的真实读数。

**性能**：纯 SVG + CSS，只动 `transform` / `opacity` / `stroke-dasharray`；JS 每 200ms 只写
`data-p` 与一个 CSS 变量。清理了 1.3KB 死样式（rail / flow-now 八条颜色规则）。

## 生命核（v16.5）

FLOW 面板那颗球重做。旧版三个毛病：7px 圆点落在 1px 细线上几乎看不见；
位置是拍出来的百分比（`ask:18` 与 `type:12` 只差 6%，`fail:78` 与 `tool:78` **完全相同**）；
只有颜色一维在变。

**现在是"活物"而不是"状态灯"。** 让它像活的东西，靠的是节奏而非美术：

| 手法 | 做法 |
|---|---|
| 站点刻度 | 轨道用 `repeating-linear-gradient` 画出 8 个刻度（零额外 DOM），位置改为命名站点；左半=你在操作台，右半=AI；八相位位置**互不重复** |
| 非对称呼吸 | 快胀慢收（36% 处到峰值，58% 已回落），不是正弦匀速——固定节拍正是"机器感"的来源 |
| 互质周期 | 呼吸 2.6s 与辉光 4.3s 互质，再加瞳孔 1.7s 反相位，三层叠加**永不精确重复** |
| 回应真实活动 | `--dsh-live` 由真数驱动：输出中=真实字/秒（÷45 归一到 0~1），工具 0.7、思考 0.55、待确认 0.4。**输出越快，核越大越亮** |
| 涟漪 | 光环随呼吸向外扩散消散 |
| 尾迹 | 取自 160 样本真实缓冲里最近三个**实际发生过的**相位，按发生距离渐隐 |
| 失败态 | 涟漪停止、只留 3.4s 慢辉光——"动"属于活着的，静下来才显出异常 |

**性能**：全程只用 `transform` / `opacity`（GPU 合成），无每帧 JS；`--dsh-live` 随 5Hz 心跳更新，
配 `transition` 平滑，不在滚动路径上做任何绘制。

## 船舱光标（v16.3）

进舱后默认箭头换成**瞄准环**（26×26 SVG data URI：细环 + 中心点 + 四向刻线，热点在中心点）。

**关键是不破坏输入手感**——分场景给不同光标：

| 状态 | 图形 | 用在哪 |
|---|---|---|
| 默认 | 细环 + 中心点 + 四刻线 | 对话正文、仪表面板 |
| 可点击 | 四角括号 + 中心点 | 按钮、链接、跳转键 |
| 输入 | I 型束 + 上下衬线 | 输入框、可编辑区 |
| 拖拽 | 中轴 + 左右人字 | 侧栏拖宽 |
| 禁用 | 细环 + 斜杠（去饱和） | 禁用按钮 |
| 检视 | 虚线环 + 中心点 | 悬停可解释的读数（弧段、故障行、用量行、工具行） |

六个状态共用 26px 画布、同一青色系、同一热点规则（中心点即落点），
**只换图形不换语义**——指向和打字的手感不会被改坏。

- 宿主的 `cursor:pointer`(15 处) / `col-resize` 都作用在元素自身，天然胜过继承，无需覆盖
- 宿主给 `.wSkVaW_crumbCurrent`、`.JObwrW_panel` 钉了 `cursor:default`，已改为继承，否则那两块会露馅
- CSP 若禁 data: 光标，整体退回系统箭头，无布局风险
- 想关掉：删掉 `.wSkVaW_root.wSkVaW_root{cursor:...}` 那一行即可

## 上下文分段弧（v16.2）

CTX 弧不再是一根青条，而是**三段**：系统提示 / 工具 schema / 对话消息。

- 数据源：`contextBreakdown = {systemTokens, toolsTokens, messageTokens}`
- 画法：SVG 半圆弧按 `strokeDasharray + strokeDashoffset` 铺三段，
  段间留 0.7 单位缝隙；三段颜色与下方 MIX 面板三行**完全同色**，
  一眼对上号（灰蓝=系统、紫=工具、青=消息）
- 悬停任一段：**不用浏览器原生 tooltip**——7px 虚线弧的可点区太窄，实测悬停不灵。
  改为每段叠一条 `stroke-width:18` 的透明命中带（`pointer-events:stroke`），
  鼠标进入后**把弧下方那行读数就地替换**为该段的名字/tokens/占比/「估算」，
  并用该段颜色着色；移开还原总量
- 弧的总跨距仍由 `contextPressure.projectedTokens / contextWindow` 决定：
  **外侧看占用多少，内侧看占的是什么**
- `contextBreakdown` 取不到时自动退回原来的一根青条（不留空白）

> 诚实标注：`contextBreakdown` 按宿主契约是**对可见表面的启发式估算**，
> 不是 provider 上报值。所以段 tooltip 带「估算」字样，且三段比例只在
> 弧的占用跨度内分配，不去改总占用数。

## 工具台账与输出流速（v16.1）

两件都是宿主已有真数，原先没接出来。

### 工具台账（AGENT 面板）

`▸TOOLS n` 下列最近四次工具调用：名字 + **真实耗时**。

- 已结束：`ToolResultNode.time - ToolResultNode.callTime`（结果时刻减配对调用时刻）
- 进行中：从 `RunningToolCall.time` 起算，青色呼吸点
- 出错：`isError` 为真则整行转红
- 扫描最近 30 个节点 + `legacy.runningCalls`，打包成字符串供 selector memo

> 窗口截断导致调用头不在内存时 `callTime` 为 null，该行显示 `—` 而不是编一个数。

### 输出流速

- **SPD = 会话均值 t/s**：`sessionStats.decodeTokens / (decodeMs/1000)`，真实 token
- **OUT = 当前字/秒**：滚动 5 秒窗口内**真实字符增量 ÷ 真实桶时长**，附 16 格火花条
- 单位刻意不同（字 vs token）：provider 的 `outputTokens` 只在
  `assistant/message`（步边界）落账，拿它算瞬时值会是"几秒 0 然后一个尖峰"的
  锯齿假数据。字符增量是唯一诚实的瞬时量，故标 `字/秒`，不换算成 token

## 玻璃悬浮（v15.3）

"文字悬浮在太空上"的实现口径——**不赌层叠**：

- 天空画进 `.wSkVaW_root`（会话区最大底片）**自己的 background**，
  `background-attachment:fixed` 钉在视口。文字永远渲染在自己背景的上方，
  层级天然成立，无需把 overlay 塞到宿主不透明层之间（v15.0 教训不再犯）
- v15.2 的 z-60 前景星层与滚动视差**移除**：天空变成"窗外"——不动，
  舱内（文字/玻璃）随滚动穿过它，悬浮感更强且零每帧重绘（131 层渐变
  逐帧移动 background-position 的成本不可接受）
- 玻璃透明度保守起步：助手气泡 76–78%、用户 62–70%、输入卡 82–88%+blur(14px)
  （blur 只给数量=1 的卡；气泡不做 backdrop-filter，量大）
- 输入座渐变改半透明（实心 0.82 收尾），消息滑到 composer 下不再撞黑墙
- 侧栏**保持舰体不透明**——本次故意不做"整页太空"，留作独立一步

验收判据：滚动顺滑不掉帧；正文在玻璃上可读（不行就回调透明度参数）。

> **v15.3.1 性能修正**：实测滚动轻微卡顿，撤掉两个逐帧昂贵项——
> `background-attachment:fixed`（Chromium 对 fixed 大背景走每帧主线程重绘，
> 131 层渐变下代价巨大；且 root 本身不滚动，去掉后视觉不变）与
> 输入卡的 `backdrop-filter:blur(14px)`（sticky 悬在滚动内容上方，
> 每帧重模糊）。卡片以更高不透明度（.88/.92）补偿失去的毛玻璃感。
> **规矩：滚动路径上禁用 fixed 大背景与 backdrop-filter。**

## 深度性能优化（v16）

进入系统后卡顿的真正根因：**会话根背景上 131 层活 CSS 渐变**。它在任何使
root 失效的事件（流式新增节点、focus/phase 属性变化、resize）时**整幅重新光栅**，
Retina 下代价巨大——v15.3.1 撤掉 fixed/backdrop 只治了滚动，没治这个。

- **星空烘焙成一张位图**：`bakeSkyURL()` 用离屏 canvas 一次性画好（底色渐层、
  三片星云、暗角、seeded 远/中星层、手写近星含光晕），`toDataURL` 后经 CSS 变量
  `--dsh-sky` 交给 root 背景。稳态渲染=1 次纹理上传 + 1 次 blit，与层数无关
- **关键路径外**：`setTimeout(...,120)` 延后烘焙；期间 root 用**单层**
  `linear-gradient` 兜底（无白闪、无活渐变）。烘焙失败也只是退回兜底，不报错
- **root 背景不再含任何活渐变**（实测 `radial-gradient` 仅剩 frame 层 2 处、
  boot 层，均非 root、非逐帧失效）
- **呼吸亮星转静态**：并入位图（省掉一个 7s 无限动画）
- **心跳让位**：`visibilitychange` 下停表，不可见时 0 React 渲染；回前台自动重启
- 气泡透明度回抬（助手 84–86%、用户 72–78%）：既补失去的毛玻璃对比，也减每像素混合

判据：进入系统、滚动长会话、流式输出三种场景都应顺滑；任务管理器里该页 CPU
空闲时应接近 0。若仍有卡顿，下一个嫌疑是流式期 scanErr 每 token 扫 40 节点——
届时改增量缓存。

## 单一心跳（v13）

v12 前全插件挂着 **~12 个 setInterval**：每个 URow 一个 70ms 缓动循环（7个）、
FLOW 200ms 采样、各组件 1000ms 时钟。v13 收敛为**工厂级单例心跳**：一个 70ms
interval + `subscribeBeat` 订阅分发，首个订阅者启动、最后一个离开自动停止。
- useClock：由心跳派生，仅跨秒才 re-render
- useEased：全部挂共享心跳（React 18 自动批处理，一次心跳合并所有数字滚动）
- FLOW：采样门槛 ≥195ms 保持 32s 窗口；think/跑/写 三段计时改用**真实 dt 累计**
  （此前假设整 200ms，现在毫秒实测）

## 安装 / 卸载

在 DSH 会话里用插件管理器（或从 GitHub 安装）：

```
plugin_manager install_bundle github:Radicas/dsh-cockpit      # GitHub（注意 github: 前缀）
plugin_manager install_bundle /绝对路径/dsh-cockpit-16.14.0.tgz  # 代码包
plugin_manager install_bundle /绝对路径/dsh-cockpit             # 本地 clone
plugin_manager remove_bundle dsh-cockpit
```

裸写 `Radicas/dsh-cockpit` 会被当成 npm 包名而拒绝，必须带 `github:` 前缀或写完整
`https://github.com/Radicas/dsh-cockpit`。本地路径必须是**绝对路径**；代码包必须是
`npm pack` 打出的 `.tgz`（GitHub 自动生成的 zip 源码包不能直接装）。

`install_bundle` 会自动把本 bundle 加入 profile 的 `dsh.profile.bundles`，无需手工挂
patch；仓库里的 `cordis.patch.yml` 只是 bundle 层的占位记录，可以不管。

改了代码后需 remove + install 重新生成模块。作用于安装到的 profile 的全部会话，可在 Settings → Plugins 停用。
